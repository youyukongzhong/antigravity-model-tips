# 模型小抄本地自进化与同步 (`/m-sync`)

当用户主动调用 `/m-sync`（可能附带了一张模型下拉列表截图、输入了新模型名称，或在收到新模型提示后直接发送 `/m-sync`）时，请按以下步骤执行：

## 步骤 1：先拉取远端公共词库更新
定位本插件所在目录（macOS/Linux 为 `~/.gemini/config/plugins/model-tips`，Windows 为 `$HOME\.gemini\config\plugins\model-tips`）：
- 执行 `git pull --ff-only` 拉取最新公共词条。

## 步骤 2：找出尚未收录的新模型
读取插件目录下的 `known_models.txt` 以及可选的 `local_models.txt`（若存在），对比以下来源中的模型名称：
1. 用户本轮上传的模型菜单截图（若有，识别图中所有模型及是否带有 `Leaving Soon` 等标签）；
2. 用户消息中提到的模型名；
3. 若用户仅发送了 `/m-sync` 且未附图，检查当前对话正在使用的模型名称是否尚未收录。

如果所有模型均已收录，直接告诉用户：“当前词库已是最新，所有模型均已在 `/m` 小抄中！”并结束。

## 步骤 3：联网查询新模型定位并写入本地独立词条（免冲突设计）
对每一个尚未收录的新模型：
1. 调用网页搜索工具查询该模型的官方发布说明，弄清它在家族中的定位（旗舰重推理 / 日常均衡主力 / 极速轻量 / 专项能力 / 即将退役）。
2. **绝不直接修改受 Git 跟踪的内置 `skills/m-*` 文件**（避免日后自动 `git pull` 冲突），而是写入 `.gitignore` 已忽略的本地专属目录：
   - 路径：`skills/m-local-<英文短横线代号>/SKILL.md`
   - `name`：`m-local-<英文短横线代号>`
   - `description`（严格控制在 38 个汉字以内，防止悬浮菜单截断）：
     `"<模型显示名> →【<4~5字职场工种>】<一句话直白适用场景>"`
     （例如：`"Gemini 4 Oxygen →【全能特派员】多模态理解极强，看图看视频拆文档找它"`）
3. 将该模型的小写核心识别关键词（如 `oxygen`）追加写入插件根目录下的 `local_models.txt`（一行一个关键词），使启动钩子将其标记为已收录，不再重复提醒。

## 步骤 4：反馈结果
用简短列表告诉用户新增了哪几条模型人话解释，并提示无需重启，现在直接在输入框敲 `/m` 就能看到新长出来的词条！
